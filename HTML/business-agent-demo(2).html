需求迭代 ★

对话 → 确认 → 开发 → 交付全流程。人只在决策点出现：确认卡上点「同意」或「要改」。

业务助理

不用进业务系统，对话即办理：查询、提单、审批，操作通过业务 API 执行并留痕。

日志链路排查

按 traceId 串起跨服务调用链，trace 级根因定位，给出证据与修复建议。只读，不改服务。

链路化数据 Mock

一句话造出一条完整业务链路的测试数据，外键自动对齐，一键写入沙箱。

巡检与维护

有界维护：巡检不占进行中通道，只有已授权的具体实施才进入迭代流水线。

发布管理

Agent 默认只生成交接计划；保护分支推送必须 operator 显式确认。发布权永远在人。

审计与权限

回执、版本指纹、操作留痕；四级角色分工，任何人口头说明都不能豁免闸门。

知识库与文档

领域文档驱动影响面判断；外部阻塞显式登记，不静默跳过。

规则

遇到外部依赖缺失，Agent 必须登记阻塞并告知影响面，严禁静默跳过或假装完成。阻塞解除后自动通知受影响需求的提出人。

确认推送保护分支？

此操作将把迭代 #20261018-07 的交付内容推送至保护分支，并通知 operator 值班群。操作将留痕并生成回执，不可由 Agent 自行撤销。
