# 向量搜索与切片召回

「切片召回 → 向量搜索」链路

---

## 一、整体链路图

```text
原始文档
   │
   ▼
┌─────────────┐
│  ① 切片      │  把长文档切成小块（chunk）
└─────────────┘
   │
   ▼
┌─────────────┐
│  ② 向量化    │  每个 chunk → Embedding 模型 → 向量
└─────────────┘
   │
   ▼
┌─────────────┐
│  ③ 入库      │  向量 + 原文 + 元数据 存入向量库
└─────────────┘
   │
   ▼  （用户提问时）
┌─────────────┐
│  ④ 查询向量化 │  问题 → 同一个 Embedding 模型 → 查询向量
└─────────────┘
   │
   ▼
┌─────────────┐
│  ⑤ 相似度检索 │  在向量库中找 Top-K 最相近的 chunk
└─────────────┘
   │
   ▼
┌─────────────┐
│  ⑥ 重排序    │  Rerank 精排，筛掉"看起来像但不对"的
└─────────────┘
   │
   ▼
  召回结果 → 拼进 Prompt → 交给大模型生成答案
```

## 二、切片（Chunking）图解

**为什么要切？** 大模型上下文有限，且整篇文档向量化会"语义糊成一团"，检索精度差。

```text
一篇 5000 字的《员工报销制度》
┌──────────────────────────────────────────────┐
│ 第一章 总则 ...                                │
│ 第二章 报销范围 ...                            │
│ 第三章 差旅报销标准 ...                        │
│ 第四章 审批流程 ...                            │
└──────────────────────────────────────────────┘
                    │ 切片
                    ▼
┌────────────┐ ┌────────────┐ ┌────────────┐
│ chunk 1    │ │ chunk 2    │ │ chunk 3    │
│ 总则+范围   │ │ 差旅标准    │ │ 审批流程    │
│ ~300字     │ │ ~300字     │ │ ~300字     │
└────────────┘ └────────────┘ └────────────┘
  每块带元数据：{来源:报销制度, 章节:第二章, 更新时间:2024-06}
```

**常见切片策略对比：**

| 策略 | 做法 | 适用 |
|---|---|---|
| 固定长度 | 每 N 字切一刀 | 简单，但易切断语义 |
| 按段落/标题 | 按自然段落或 Markdown 标题切 | 结构清晰的文档 |
| 语义切片 | 按语义相似度聚类切分 | 长文、无结构文本 |
| 重叠切片 | 相邻块重叠 10%~20% | 防止边界信息丢失 |
| 父子切片 | 子块检索、父块召回 | 兼顾精度与上下文完整 |

> 关键点：**切片大小要匹配问题粒度**。问"差旅标准"就该命中"差旅"那块，而不是整篇制度。

## 三、向量化图解

```text
"差旅住宿标准为每晚 500 元"
            │
            ▼  Embedding 模型（如 bge / text-embedding-3）
            │
   [0.12, -0.87, 0.33, ..., 0.05]   ← 一个高维向量（如 768/1024 维）
```

**核心直觉：语义相近 → 向量距离近**

```text
向量空间（降维示意）：

         ● "住宿费报销上限"
    ● "酒店标准500元"
              ● "差旅住宿标准"     ← 语义接近，聚在一起
                          ● "出差补贴"
                                         ● "发票开具流程"
                    ● "审批签字"              ← 语义远离
```

## 四、向量搜索图解

用户问：**"出差住酒店能报多少？"**

```text
① 问题向量化
   "出差住酒店能报多少" → [0.11, -0.85, 0.30, ...]

② 在向量库中算相似度（余弦相似度）
   ┌──────────────────────────────┬──────────┐
   │ chunk                        │ 相似度    │
   ├──────────────────────────────┼──────────┤
   │ 差旅住宿标准为每晚500元        │ 0.91 ✅  │
   │ 出差补贴每天100元             │ 0.72    │
   │ 发票开具流程...               │ 0.35    │
   │ 审批签字流程...               │ 0.21    │
   └──────────────────────────────┴──────────┘

③ 取 Top-K（如 K=5）→ 送 Rerank 精排

④ 最终召回：
   "差旅住宿标准为每晚500元（一线城市），
    二线城市400元..." → 拼入 Prompt
```

**相似度度量：**

```text
cos(A,B) = (A·B) / (|A|·|B|)     值越接近 1 越相似
```

## 五、切片召回的关键问题与对策
> 尽量优先从源头解决 —— 原始文档按照符合切片策略的固定的格式
> 原始文档 -> 整理成业务知识库文档 -> 进入知识库

| 问题 | 现象 | 对策 |
|---|---|---|
| 切片太大 | 召回噪声多、上下文冗余 | 缩小 chunk，或用父子切片 |
| 切片太小 | 语义不完整、答非所问 | 增大 chunk 或加重叠 |
| 切断语义 | "500元"和"住宿"被切到两块 | 按段落/标题切 + 重叠 |
| 语义漂移 | 关键词匹配不上同义表达 | 用 Embedding 而非纯关键词 |
| 检索不准 | Top-K 里混入相似但无关内容 | 加 **Rerank 重排序** |
| 多义问题 | "苹果"指水果还是公司 | 元数据过滤 + 混合检索 |

## 六、混合检索：向量 + 关键词

单靠向量搜索对**专有名词、编号、精确匹配**不敏感，所以常做混合：

```text
用户问题
   │
   ├──► 向量检索（语义）──┐
   │                      ├──► 融合排序（RRF/加权）──► Top-K
   └──► BM25 关键词检索 ──┘
```

```text
例：查"工单 WO-2024-0912 的处理进度"
  向量检索：可能召回"工单处理流程"（语义像但不对）
  BM25    ：精确命中"WO-2024-0912" ✅
  融合后：精确编号那条排第一
```

## 七、一图总结

```text
        文档 (如果是父子切片： -> 切大块的)
    
         │ 切（xiao）片（按语义/段落，带重叠）
         ▼
     [chunk1][chunk2][chunk3] ...
         │ 向量化（Embedding）
         ▼
   向量库：向量 + 原文 + 元数据
         ▲
         │ 查询向量化
         │
      用户问题
         │
         ▼
  相似度检索 Top-K ──► Rerank 精排 ──► 召回 chunk
         ▲
         │ 混合：BM25 关键词检索
         │
      拼入 Prompt → 大模型生成答案
```

**一句话记忆**：**切得准（切片）→ 表示好（向量化）→ 找得对（相似度+混合+重排）**，三步决定 RAG 召回质量。
