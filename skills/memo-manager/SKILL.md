# Memo Manager — 备忘录维护技能

## 触发条件

当用户发送以下内容时自动触发：
- 一段或多段文字内容（需要总结归档）
- 一张或多张图片（需要提取信息并归档）
- 文字与图片的混合内容

## 工作目录

Obsidian 仓库根目录：
`/Users/gongyi/Documents/Obsidian/KnowledgeOS/`

三个维护目标：
| 文件夹 | 用途 |
|--------|------|
| `备忘录/` | 存放按日期命名的 Markdown 文档 |
| `Images/` | 存放图片资源 |
| `skills/` | 存放技能文档 |

## 工作流程

### 第一步：内容提取

- **文字内容**：提取关键信息、日期、主题，总结为结构化要点
- **图片内容**：通过视觉分析提取图片中的关键信息（文字、图表、场景等）
- **混合内容**：分别处理文字和图片，建立关联关系

### 第二步：日期判定

1. 如果内容中包含明确的日期信息 → 使用该日期
2. 如果没有日期信息 → 使用当天日期
3. 日期格式统一为 `YYYY-MM-DD`（如 `2026-08-20`）

### 第三步：备忘录文件处理（高效读写策略）

**核心原则：先查文件名是否存在，不盲目读取内容。**

1. 用 `ls` 或 `test -f` 检查 `备忘录/YYYY-MM-DD.md` 是否存在
2. **文件不存在** → 直接创建新文件，写入内容（完全不读取）
3. **文件已存在** → 读取已有内容，先判断新旧内容是否为**同一主题的更新**：
   - **同一主题更新**（如晚点动态、状态变化、行程变更等）→ 执行**覆盖整合**：
     1. 用新信息覆盖旧条目中对应的过时字段（新值优先）
     2. 保留旧条目中仍然有效的信息（新内容未提及的部分）
     3. 条目标题的时间更新为最新时间
     4. 删除旧的独立条目，**只保留一份整合后的完整条目**，放在文件最顶部
   - **不同主题** → 新条目插入文件顶部（倒序），旧条目保持不动
4. 同一日期多个条目时，最新条目放在文件顶部（倒序）
5. 备忘录文件夹中的文件整体按日期从新到旧排列

> 注意：不要每次都读取文件内容。只有确认文件已存在且需要追加或整合时才读取。

### 第四步：图片处理

- 将图片复制/移动到 `Images/` 文件夹
- 命名规则：`关键信息描述.扩展名`
  - 示例：`会议白板记录.jpg`、`需求截图-登录流程.png`、`架构图-系统拓扑.jpg`
- 命名要求：
  - 简洁、描述性，能从文件名看出图片核心内容
  - 使用中文命名，多个词语用 `-` 连接
  - 禁止使用时间戳或无意义的数字命名
  - 如果同名文件已存在，在文件名后追加序号（如 `会议白板记录-2.jpg`）

### 第五步：图片引用

在备忘录文档中通过相对路径引用图片：
- 相对路径格式：`../Images/文件名.扩展名`
- 使用 Markdown 链接语法（非嵌入图片，不要用 `![]()`）：

```markdown
[相关图片: 图片描述](../Images/文件名.jpg)
```

## 备忘录文档格式模板

**不要写文件级标题**（如 `# 2026-08-20 备忘录`）。文件名已包含日期信息，重复写标题浪费空间。

文件直接以条目开头，多个条目用 `---` 分隔，最新条目在最上面：

```markdown
## HH:MM 主题标题

**摘要**：一句话概括

**要点**：
- **关键词**：值
- ==重要信息高亮==
- <span style="color: #e67e22">状态：已支付</span>

**相关图片**：
- [图片描述](../Images/图片文件名.jpg)

---

## HH:MM 另一个主题

...
```

### Markdown 样式指南

根据内容类型适当使用以下语法增强可读性：

| 语法 | 用途 | 示例 |
|------|------|------|
| `**bold**` | 标签、关键词 | `**订单号**：ED30257756` |
| `==highlight==` | 重要数值、日期 | `==4小时33分==` |
| `<span style="color: ...">` | 状态、强调 | `<span style="color: #27ae60">状态：已支付</span>` |
| `> blockquote` | 备注说明 | `> 中转站需重新检票` |
| 表格 | 多条结构化数据 | 车次 \| 路线 \| 时间 \| 座位 |

颜色参考：
- 绿色 `#27ae60` → 完成、已支付、正常
- 橙色 `#e67e22` → 待处理、进行中、注意
- 红色 `#e74c3c` → 异常、取消、错误
- 蓝色 `#2980b9` → 信息提示

不要过度使用样式，关键信息点到为止。

## 处理完成后的输出

处理完成后，向用户简要说明：
1. 创建/更新了哪个备忘录文件
2. 提取了哪些关键内容
3. 图片移动到了哪里、命名是什么

## 注意事项

1. 内容总结要精炼，提取核心信息，去掉冗余表述
2. 图片命名要有意义，能从文件名直接看出图片内容
3. 同一主题的更新执行**覆盖整合**：新信息覆盖旧值、有效旧信息保留、删除旧条目，整合后的条目放最顶部；不同主题的新条目才追加在文件顶部（倒序排列）
4. 图片引用使用相对路径链接，不嵌入图片
5. 如果用户发送的内容没有明确主题，根据内容自动归纳主题标题
6. 处理图片时保留原始格式（jpg/png/gif 等）
7. **不写文件级标题**，文件名即日期，直接以条目 `## HH:MM 主题` 开头
8. **高效读写**：先 `ls`/`test -f` 查文件是否存在，不存在直接写，存在才读取追加
